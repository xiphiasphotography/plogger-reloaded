# Stored description XSS hotfix

Album, collection and photograph descriptions historically return raw HTML by default. The alternate `strip`, `code` and `clean` getter modes and import-time `nl2br()` conversion confirm that formatting was supported. Escaping all descriptions as plain text would remove that behavior.

Default description getters now apply a formatting-only policy at render time. Allowed tags: `b`, `strong`, `i`, `em`, `u`, `s`, `br`, `p`, `ul`, `ol`, `li`, `blockquote`, `code`, `pre`. All attributes are discarded. Other elements are unwrapped to inert text; images, scripts, links, styles, SVG and embedded content cannot retain active behavior. **Compatibility restriction:** arbitrary rich HTML, custom styles and clickable description links are no longer supported. Their original database values remain available for editing and are not rewritten.

The sanitizer uses native DOM parsing with network access disabled and reconstructs output solely from allowed tag names and escaped text. It never serializes untrusted attributes. Without DOM, descriptions fall back to escaped text with line breaks; formatting markup is displayed literally. No external library or mandatory runtime dependency was introduced.

Line breaks are preserved, including CRLF and legacy `<br />` plus newline storage, without doubling legacy breaks. Preformatted text retains its newlines. Parsed entities are escaped once, so existing `&amp;` values retain their display rather than becoming `&amp;amp;`. UTF-8 escaping uses ENT_QUOTES and ENT_SUBSTITUTE. Edit fields escape the original stored string so the browser field value remains unchanged, including literal entity spellings.

All four bundled themes were reviewed. Their description body output uses the shared getters. Lucid's collection/album title and alt attributes now request the additive `attribute` getter mode, which supplies escaped plain text. SEO description attributes use the same policy. Administrative list output uses the shared getters; description edit fields have explicit UTF-8/ENT_QUOTES escaping. Inline-edit RPC description responses are sanitized before insertion into administrative HTML. The existing getter names, parameters and `strip`/`code`/`clean` modes remain available; `strip` is a plain-text API and custom callers must escape it for their output context.

Tests seed existing malicious descriptions through the synthetic PDO fixture and inspect all four themes at collection-list, album-list, photo-list and photo-detail levels, administrative lists and inline-edit responses. Helper regressions cover scripts, event handlers, malformed SVG/MathML/iframe markup, entities, formatting and line breaks. No database migration, content cleanup or original-image operation is performed. The prior login `r` and gallery `jump-menu` reflected XSS regressions remain in the same suite.

Remaining limits: private `dgp2026` and other custom themes are unavailable for runtime review; custom raw database access can bypass the getters. Caption/name/comment escaping, broader SQL/CSRF/authentication defenses and other Phase 2 release gates remain separate work. This hotfix does not establish public-release readiness.

Validation: strict lint passed for 134 PHP files on PHP 8.1.34, 8.2.34, 8.3.35 and 8.4.26. Each version passed 32 PHPUnit tests with 720 assertions, including inherited theme signatures, stored-description fixtures and both reflected XSS regressions. Tooling PHPStan level 3 passed; application analysis on PHP 8.3 retains 165 findings without suppressions. CRLF-aware diff checks passed. No native database integration, real-browser/nginx/PHP-FPM testing, private-theme testing, GitHub Actions run or deployment was performed for this render-only hotfix.
